API Documentation

This instance exposes a JSON-based REST API under /api/v1/. All responses use the format:

{ "success": true, "data": { ... }, "error": "..." }

Authentication and limits

Send an account key using Authorization: Bearer <key> or X-API-Key: <key>. Bearer takes precedence if both are sent. Create a separate key per tool in Account settings.

Public paper reads and keyword/semantic searches work without a key, so a successful public request does not prove authentication. Use GET /api/v1/account to verify your key and see its capabilities. Account keys unlock Deep Search and metadata-ingestion requests; they do not grant admin access or higher limits.

Limits per IP: 1,000 requests/minute overall; 60 research queries/minute (each batch item counts); 6 paper requests/minute; 20 legacy PDF searches/minute. A busy operation can also return 429. Respect Retry-After.

Python clients: standard urllib.request works on /api/v1/* without a user-agent override. A descriptive application User-Agent is optional and does not grant access. Protected endpoints still require credentials.

Research API for agents

OpenAPI schema. The research endpoints use consistent camelCase fields, full abstracts, author names, category arrays, original submission months, arXiv links, snippets, and known repository links. Existing search endpoints keep their legacy fields for compatibility.

GET /api/v1/research
Search using q (a question or paragraph), mode=hybrid|semantic|keyword|deep, category=cs.GR, since=2025-01, until=2027-01, or year=2026. Use YYYY or YYYY-MM. Dates are inclusive at the start and exclusive at the end, based on the original arXiv submission month. Use limit=20 (max 100), minSimilarity=0.5, and optional recencyBoost=0.2 (0–1).

Hybrid ranking combines lexical and vector ranks, prioritizes exact names, and optionally boosts recency. It is a deterministic rerank, not a learned cross-encoder. similarity is cosine similarity or null for lexical-only matches; score is a ranking score, not a confidence probability. A positive minimum similarity excludes lexical-only matches.

mode=deep searches prepared full-paper chunks and returns snippet, section, and chunkId. Coverage depends on extracted and embedded papers. Numerical values and tables should still be checked against the original PDF.

Cold queries return HTTP 202 with complete:false and job:{id,statusUrl,retryAfterSeconds}. Poll statusUrl until ready, then repeat the original search. Use waitSeconds=3 (max 8) for a brief wait. An empty keyword fallback is not a completed semantic search. effectiveMode reports the retrieval used. HTTP 206 and partial:true indicate incomplete retrieval without a pending job. Check partial and warnings even when complete is true.

POST /api/v1/research/batch
Send up to four query objects in {"queries":[{"q":"Gaussian streaming","mode":"hybrid"},{"q":"ocean foam","category":"cs.GR"}]}. Results stay in input order; inspect each item's success and job status. Each item may include waitSeconds.
POST /api/v1/papers/{id}/request
With an account key, fetch missing public arXiv metadata and queue embedding preparation. No admin token needed. Source/PDF downloads remain administrative. Check embeddingQueued and statusUrl before requesting similar papers.

codeLinks contains repository links found in paper metadata. codeAvailability:"linked" means a link was found, not that a release was verified; "unknown" does not mean code is unavailable.

import json, urllib.parse, urllib.request
params = urllib.parse.urlencode({
    "q": "ocean whitecap foam rendering",
    "mode": "hybrid", "category": "cs.GR", "since": "2025-01"
})
request = urllib.request.Request(
    "https://arxiv.gg/api/v1/research?" + params,
    headers={"User-Agent": "arxivgg-python/1.0 (+https://arxiv.gg)"}
)
with urllib.request.urlopen(request, timeout=25) as response:
    result = json.load(response)["data"]
# Check complete, job, and warnings before treating this as final results.
for hit in result["results"]:
    print(hit["paper"]["title"], hit["paper"]["arxivUrl"])

Papers




	GET /api/v1/papers/{id}
	
Get paper metadata, citation count, and references.






	GET /api/v1/papers/{id}/citations
	
Get references cited by this paper.






	GET /api/v1/papers/{id}/cited-by
	
Get papers that cite this paper.

	
Query: limit (default: 50)






	GET /api/v1/papers/{id}/graph
	
Get citation graph data (nodes and edges) for visualization.






	GET /api/v1/papers/{id}/similar
	
Get semantically related papers and related-work map data.

	
Query: limit (default: 80, max: 160). Requires the paper to be ready for related-work search.






	POST /api/v1/papers/{id}/fetch
	
Administrative source/PDF fetch. For account-key metadata ingestion, use POST /api/v1/papers/{id}/request.

	
Query: pdf=true, source=true (default), embedding=true






	GET /api/v1/papers/{id}/export/{format}
	
Export paper metadata. Formats: bibtex, ris, json









Search




	GET /api/v1/search
	
Full-text search papers by title and abstract (FTS5).

	
Query: q (required), category, limit (default: 20)






	GET /api/v1/search/quick
	
Quick lookup for IDs, titles, authors, keywords, and categories.

	
Query: q (required), limit (default: 10)






	GET /api/v1/search/streamNEW
	
Stream Quick, Search, or Deep results via Server-Sent Events (SSE) for real-time UI updates.

	
Query: q (required), mode=quick|search|deep (default: search), category, limit (default: 100)

	
Header: Accept: text/event-stream






	GET /api/v1/search/semanticNEW
	
Search ideas across abstracts using vector similarity.

	
Query: q (required), limit (default: 20)

	
Falls back to Quick results with fallback=true when abstract Search is unavailable.






	GET /api/v1/search/pdf
	
Search within downloaded PDF content.

	
Query: q (required), limit (default: 50), fuzzy=true









EmbeddingsNEW




	POST /api/v1/papers/{id}/embeddings
	
Generate a paper profile. Response includes hasEmbedding, mapReady, and generator.






	POST /api/v1/embeddings/generate
	
Legacy bulk generation is retired. Prepare one paper with POST /api/v1/papers/{id}/embeddings; the request may return queued status.

	
Query: limit (optional, process only N papers)

	
Header: Accept: text/event-stream for SSE progress updates









Categories & Stats




	GET /api/v1/categories
	
List all categories with paper counts.






	GET /api/v1/stats
	
Get cache statistics (total papers, downloads, queue status).







Examples


# Get paper metadata
curl "{{.BaseURL}}/api/v1/papers/1706.03762"

# Search papers (keyword)
curl "{{.BaseURL}}/api/v1/search?q=transformer&limit=10"

# Semantic search (requires embeddings)
curl "{{.BaseURL}}/api/v1/search/semantic?q=attention+mechanism&limit=10"

# Fetch paper with embedding generation
curl -X POST "{{.BaseURL}}/api/v1/papers/2301.00001/fetch?embedding=true"

# Generate embedding for a paper
curl -X POST "{{.BaseURL}}/api/v1/papers/1706.03762/embeddings"

# Get citation graph
curl "{{.BaseURL}}/api/v1/papers/1706.03762/graph"

# Export as BibTeX
curl "{{.BaseURL}}/api/v1/papers/1706.03762/export/bibtex"
